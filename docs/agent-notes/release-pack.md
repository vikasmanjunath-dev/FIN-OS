## Findings (honest list, most important first)

1. **Account deletion is incomplete** (`supabase/delete_account.sql`): proven in real Postgres, 9 tables keep the user's rows
   (`alerts`, `push_subscriptions`, `alert_preferences`, `health_score_history`, `memory_embeddings`, `user_behavior`,
   `document_ai_log`, `couple_links`, and `profiles` on the live project). Replacement ready in
   `mobile/scripts/release-sql/delete_account_complete.sql` (proved complete; idempotent; denies anon). Integrator: copy over `supabase/delete_account.sql`.
2. **`voiceagent/schema.sql` begins with `DROP TABLE IF EXISTS agent_memories`**: re-running destroys all voice memories, while
   `supabase/README.md` says to run it "if missing". Shared file, not edited.
3. **`alerts/schema.sql` is not re-runnable** (`CREATE POLICY user_read_own_alerts` without DROP IF EXISTS), contradicting the "every file is idempotent" sentence for the repo as a whole (true for `supabase/*.sql`). Shared file, not edited.
4. **No usable backend in a store build**: `ENDPOINTS` host defaults to the Expo dev machine / `10.0.2.2` / `127.0.0.1`, URLs are `http://`. Android release blocks cleartext, iOS ATS blocks non-local `http`. Live prices and Arya chat therefore do not work for a store user unless they run their own HTTPS backend. The store copy does not advertise them. Not changed (product decision).
5. **Permissions in the built app exceed `privacy.ts` PERMISSIONS**: `VIBRATE`, `USE_FINGERPRINT`, `RECEIVE_BOOT_COMPLETED` (prebuilt manifest + library manifests). No prompts, but Play lists them. Needs a decision/edit in `lib/privacy.ts` and `privacy.test.mts`.
6. **`expo-av` is installed and unused**; only kept harmless by `microphonePermission:false` + `RECORD_AUDIO` in blockedPermissions. Remove from `package.json` when convenient.
7. UI defects seen in the captures (not mine to fix): right-aligned inputs clip long values on Budget ("950" for 95000) and Goals; the Portfolio tab title wraps "Portfoli/o" at 430 px with the three header buttons; Settings "Mobile v1.0.0" is hard-coded (`app/settings.tsx:337`).
8. Money Score and Retirement on the synthetic profile: retirement shows "1% chance" (profile is not tuned for marketing), so retirement was left out of the store set on purpose.
9. Bundle (Android Hermes export, 14 Oct, main tree): **3.5 MB** `.hbc`, 1519 modules; sources: react-native 2.3 MB, app 1.66 MB (255 files; biggest `lib/i18nHi.ts` 86 KB), supabase-js sub-packages about 0.8 MB (auth 436 KB, storage 113 KB, postgrest 108 KB, realtime 106 KB: realtime and storage are not used by the app). Expo's inline-requires already defers module evaluation; a native bundle is a single file so `import()` does not split it. No change worth the risk before release. Possible later win: import only `@supabase/auth-js` + `postgrest-js` instead of `supabase-js` (about 220 KB of source).
10. `allowBackup:false` means no Android auto-backup: users changing phone rely on the encrypted backup feature. Intentional; stated in the checklist.
